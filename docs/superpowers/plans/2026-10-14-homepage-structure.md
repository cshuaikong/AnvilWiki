## 当前首页的问题

1. 首屏大标题和留白较多，主要文章入口位于下方。
2. QuickStart 与 Most read 都重复栏目入口，未帮助读者选择具体文章。
3. Most read 是静态配置，没有浏览量排序依据；应改为 Featured guides / 编辑推荐。
4. 最新文章只有占位内容，不能通过结构重排解决内容不足。
5. 首屏和底部主按钮指向 example.com，需要实际实施时改为有效站内入口。
6. Explore 中的教程、领码与 Boss 步骤尚未针对当前游戏核实。

## 推荐顺序：紧凑内容入口

1. 顶部：共用 Logo + 已有栏目下拉 + 搜索/主题/语言。
2. 紧凑介绍：站名 + 一句真实定位 + 显著搜索入口。桌面介绍块约 180–220px；避免强制占据一整屏。
3. 任务入口：新手入门 / 查找资料 / 对比选择 / 浏览全部。只绑定已存在的文章或栏目；内容不足时减少入口。
4. 精选攻略 + 入门路线：桌面 2:1 布局；主区 3–4 篇编辑选择的文章，侧栏 3 步阅读路线。移动端先精选再入门路线。
5. 按栏目浏览：当前导航分类，各栏目最多 3 条文章 + 查看全部；空栏目不在首页占一个空卡片。
6. 最近更新：最多 4–6 条紧凑列表，显示实际 lastModified ?? date；查看全部指向 /recent/。
7. 可选 FAQ：只放真实已核实的 3–4 个常见问题和已有全文链接；没有可靠内容则不显示。
8. 页脚：站点介绍、资源、法律页面；删除重复的大型收尾 CTA。

## 备选：分类目录优先

紧凑介绍与搜索 → 栏目目录与文章 → 入门路线 + 最近更新 → 页脚。适合文章数量更多、读者明确知道要查哪个栏目时采用。启动期先采用推荐版。

## 内容与实现边界

- 本轮仅出方案图，未修改首页代码、分类配置或游戏事实。
- 图中的具体文章标题为策划样例，不表示仓库已存在这些文章；实施时只显示真实已发布内容。
- 保留现有分类 URL。参考站的 Mechanics / Aircraft / Vehicles 等只能作为后续分类规划候选，不直接重命名现有目录。
- 对标站定位 Roblox Plane Crazy，而本项目 site.game.platform 当前为 steam；先确认目标游戏身份再改游戏信息与栏目体系。
- 不复制竞争对手文案、数据或图片；只借鉴信息组织方式。
- 不填写虚构活跃人数、访问量或更新统计，不以代码部署时间冒充内容验证时间。
- 继续纯 Astro、结构化 locale JSON 和集合读取；搜索复用现有 Pagefind 弹窗。
- 精选文章使用 locale JSON 的真实路径配置；栏目和近期列表从 wiki 集合读取，categoryIndex 不进入文章列表。
- 广告沿用 env 门控，不在方案中增加首屏遮挡或空广告占位；有实际广告需求再评估正文模块之间的位置。
